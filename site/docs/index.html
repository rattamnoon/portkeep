Portkeep documentation

Portkeep is a macOS menu bar app for the port forwards you open every day. You name each tunnel once, switch it on when you need it, and Portkeep keeps it up: it reconnects after sleep or a dropped session, and when something breaks it says which tunnel, why, and what to do.

What Portkeep does#

Each tunnel is a named local port (say 127.0.0.1:3306) that Portkeep opens by running a tool you already use: ssh, aws ssm start-session, kubectl port-forward, gcloud compute start-iap-tunnel, cloudflared access tcp, or a command of your own. Portkeep then:

  • shows Connected only once the local port actually accepts connections, and checks it again every 10 seconds;
  • restarts the tool when it exits or stops answering, waiting 1 s, 2 s, 4 s … up to 60 s between tries, and spends no tries while the Mac is offline;
  • checks that the local port is free before starting, and names the process holding it if not;
  • turns back on the tunnels that were on when it quit;
  • explains failures in plain words, with the fix in the row's ⋯ menu.

It uses your existing ~/.ssh/config, AWS profiles, kubeconfig and sign-ins, and stores no passwords, keys or tokens.

Install#

Portkeep needs macOS 14 Sonoma or later, on Apple silicon or Intel.

Homebrew (recommended)#

brew install --cask rattamnoon/tap/portkeep

This also puts the portkeep command on your PATH. Update with brew upgrade --cask portkeep.

Download#

Get Portkeep-<version>.dmg from GitHub Releases, open it and drag Portkeep to Applications.

Build from source#

brew install xcodegen
git clone https://github.com/rattamnoon/portkeep.git && cd portkeep
xcodegen generate
xcodebuild -scheme Portkeep -configuration Release -derivedDataPath build build
ditto build/Build/Products/Release/Portkeep.app /Applications/Portkeep.app
open /Applications/Portkeep.app

Builds from source are ad-hoc signed, so macOS warns when you open a copy on another Mac.

Install the tools your tunnels use#

Portkeep runs command-line tools rather than bundling them. Install the ones for the methods you use, for example:

brew install awscli kubectl cloudflared
brew install --cask session-manager-plugin google-cloud-sdk

ssh comes with macOS. Settings › Tools shows which tools Portkeep found.

First launch#

Releases aren’t notarized yet, so the first time you open Portkeep macOS may say it can’t check the app for malicious software. Either right-click Portkeep in Applications and choose Open, or run:

xattr -dr com.apple.quarantine /Applications/Portkeep.app

Portkeep lives in the menu bar: look for a bracket-and-dot icon [•]. It has no Dock icon unless one of its windows is open. On the very first launch, with no tunnels yet, it opens the Settings window so you can see where to start.

Can’t see the icon? On a Mac with a notch, a crowded menu bar can hide it. Open Portkeep again from Finder or Spotlight and the Settings window comes up. Every tunnel can be started and stopped from there too.

Add your first tunnel#

  1. Click the Portkeep icon in the menu bar, then Add Tunnel…
  2. Pick a method in the Connect with list on the left: SSH, AWS SSM, Kubernetes, Google Cloud IAP, Cloudflare Access or Custom Command.
  3. Fill in the Name and the method’s fields. Hosts from ~/.ssh/config, AWS profiles from ~/.aws/config and kube contexts are offered in pickers next to the fields.
  4. Choose a Local port, and optionally a Group and a Tag. The Runs box at the bottom shows the exact command Portkeep will run.
  5. Press Test Connection to check it, then Add Tunnel. Switch it on from its row in the menu, and point your client at 127.0.0.1 on the local port.

Adding tunnels covers every field, and Connection methods has a section and an example for each method.
