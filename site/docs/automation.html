Command line and URLs

Everything the switches and the editor do, you can also do from the terminal with the portkeep command, with JSON in and out for scripts, or from any app that opens links with a portkeep:// URL. Scripts can read the same status the menu shows.

Installing the command#

If you installed Portkeep with Homebrew, portkeep is already on your PATH. Otherwise, use Settings › General › Install Command Line Tool…. It links the tool inside the app (Portkeep.app/Contents/Resources/bin/portkeep) into:

  • /usr/local/bin when Portkeep can write there, or else
  • ~/.local/bin, creating it if needed, and tells you if that folder isn’t on your PATH yet.

If neither works it shows a sudo ln -sf … line to paste into Terminal, with a Copy Command button. The same tool runs the MCP server for AI assistants.

Commands#

portkeep list                        # every tunnel: name, group, port, state
portkeep status "Orders MySQL"       # one tunnel; exits 0 when connected
portkeep start "Orders MySQL"        # also stop, toggle
portkeep start "Orders MySQL" --wait # wait until it connects or fails
portkeep start-group Development     # also stop-group
portkeep start-all                   # also stop-all
portkeep open                        # open Settings
portkeep open Redis                  # open Settings on that tunnel
portkeep test "Orders MySQL"         # connect once and stop, like Test Connection
portkeep logs "Orders MySQL" -n 20   # the end of its log
portkeep help
CommandDoes
list (or ls)Prints a table of every tunnel: NAME, GROUP, PORT, STATE and DETAIL. DETAIL is the status line, or “since 14:05” for a connected tunnel.
status <name>The same table for one tunnel. Without a name, it is list.
start <name>Switches the tunnel on (switching off any tunnel on the same port).
stop <name>Switches it off.
toggle <name>Switches it on if it is off, otherwise off.
start-group <group>
stop-group <group>		Every tunnel in the group, like the group switch in the menu.
start-all
stop-all		Every tunnel, like the master switch.
open [name]Opens the Settings window, on that tunnel if you name one.
get <name>One tunnel’s settings and state, as JSON.
test <name>Connects once and stops again, as Test Connection does, and prints the result, with the log when it fails. Exits 0 when it connected. test --config '<json>' tests settings without saving them.
logs <name> [-n 50]The last lines the tunnel’s tool printed (up to 500).
add, edit, remove, duplicateChange tunnels. See JSON and changing tunnels.
add-group, add-tagAdd an empty group or a tag, with --color #RRGGBB.
groups, tagsGroups and tags with their colours and how many tunnels each has.
methods [method]Each connection method’s fields, defaults and an example tunnel.
discoverWhat this Mac has configured: Host aliases in ~/.ssh/config, AWS profiles and their regions, kube contexts, which tools are installed, and the ports tunnels use.
mcpRuns the MCP server on standard input and output.
versionThe version of Portkeep the tool belongs to.
  • Names and groups match ignoring case. A tunnel’s id from tunnels.json works in place of its name. If several tunnels share a name, use the id.
  • Every other command talks to the running app through control.sock in its data folder, launching Portkeep in the background first if it isn’t running (it waits up to 10 seconds for it); nothing comes to the front. Changes go through the same checks as the editor and show in the menu straight away.
  • An unknown name stops with a message that lists the tunnels there are, such as No tunnel named Ordres. Tunnels: Orders MySQL, Redis.
  • list and status without --json read status.json and never start Portkeep. If it isn’t running they show every tunnel as off with “Portkeep isn't running”.
  • start, stop and toggle return straight away and print nothing, as before. With --wait [seconds] (15 by default, at most 60) they wait until the tunnels connect or fail, print their states, and exit 1 if any didn’t connect.

States#

The STATE column (and state in status.json) is one word:

StateIn the menu
offOff
connectingConnecting…
connectedConnected
standing-byStanding by · starts when an app connects
reconnectingReconnecting…
blockedPort … is in use
failedA failure message

Exit codes#

CodeWhen
0Success. For status: the tunnel is connected.
1For status: not connected. For test and start --wait: it didn’t connect. Also: no tunnel or group by that name, a change Portkeep refused (the message says which field and why), Portkeep couldn’t be started, or no status.json yet (list/status say “no status yet; open Portkeep first.”).
2For status: several tunnels have that name and only some are connected.
64Unknown command or option, a command missing its name or group, or input that isn’t JSON.

start and stop return as soon as the request is sent unless you add --wait:

portkeep start "Orders MySQL" --wait && mysql -h 127.0.0.1 -P 3306 orders

JSON and changing tunnels#

Add --json to any command that reads (list, status, get, test, logs, groups, tags, methods, discover, and start/stop/toggle) to get JSON instead of a table. A tunnel comes out in the same shape as in tunnels.json, plus what it is doing now:

$ portkeep get "Prod MySQL" --json
{
  "group" : "Production",
  "id" : "9F1C2A4E-6B3D-4C1A-9E57-2D8B0F6A1C33",
  "localPort" : 3307,
  "method" : { "ssm" : { "profile" : "prod", "region" : "ap-southeast-1", "target" : "i-0a3f5c9e2b7d41f08", … } },
  "name" : "Prod MySQL",
  "state" : "failed",
  "status" : "AWS sign-in expired for profile prod.",
  "reason" : "ssoExpired",
  "hint" : "The AWS SSO session expired. Run: aws sso login --profile prod — then start the tunnel again.",
  …
}

A tunnel that is failed, reconnecting or blocked also has reason, a fixed word for scripts (ssoExpired, authFailed, hostKeyChanged, hostUnreachable, portInUse, toolMissing and so on), and hint, what to do about it in English. A blocked one has blockedBy with the process holding the port.

Changes take JSON too, after --json, from a file with -f file.json, or on standard input. They print the result as JSON, and any warning (a port another tunnel shares, or one something else is using) on standard error.

portkeep add --json '{"name": "Grafana", "group": "Production", "localPort": 3000,
  "method": {"kubernetes": {"context": "prod", "namespace": "monitoring",
                            "resource": "svc/grafana", "remotePort": 3000}}}'
portkeep add -f orders.json --start         # and switch it on
portkeep edit Grafana --json '{"localPort": 3001}'   # only the fields to change
portkeep duplicate Grafana --name "Grafana staging"
portkeep remove "Grafana staging" --yes
  • add takes a tunnel without an id; one is assigned. name, localPort and method are required, and everything else has the editor’s defaults (group Other, SSH mode local, AWS profile default, namespace default…). portkeep methods ssm lists a method’s fields.
  • edit takes only the fields to change (a JSON merge patch): nested objects merge, null removes an optional field, and a method with a different key replaces the method. A running tunnel restarts only when how it connects changed.
  • The rules are the editor’s: a name nobody else has, ports from 1 to 65535, every required field filled, at most one tag. An unknown field, such as port for localPort, is an error rather than ignored. The message names the field.
  • remove asks before deleting when you run it in a terminal; in a script, pass --yes.
  • Nothing writes tunnels.json but the app, so it is never written by two programs at once.

status.json#

Portkeep rewrites ~/Library/Application Support/Portkeep/status.json shortly after every change, for the command and for your own scripts. It is written by the app and never read back. At quit it is written once more with "running": false and every state off.

{
  "pid" : 4120,
  "running" : true,
  "tunnels" : [
    {
      "connectedSince" : "2026-10-17T06:12:40Z",
      "group" : "Production",
      "id" : "9F1C2A4E-6B3D-4C1A-9E57-2D8B0F6A1C33",
      "name" : "Orders MySQL",
      "port" : 3306,
      "state" : "connected",
      "status" : "Connected · 2h 14m"
    }
  ]
}
  • pid is Portkeep’s process; if no process with that pid is running, the file is left over from a crash and every tunnel is off.
  • status is the menu’s status line in the app’s language, as of the last change, so its duration goes stale. Use connectedSince (present only while connected) for timing.

For example, with jq:

jq -r '.tunnels[] | select(.state != "off") | "\(.name)\t\(.state)"' \
  ~/Library/Application\ Support/Portkeep/status.json

portkeep:// URLs#

The same actions work as URLs, from anywhere that opens links: Shortcuts, Raycast, Alfred, a browser bookmark, or open in a script.

portkeep://start?name=Orders%20MySQL
portkeep://stop?group=Production
portkeep://toggle?all
portkeep://open
portkeep://open?name=Redis
  • The action is start, stop, toggle or open.
  • The target is name= (a tunnel name or id), group=, or all. Names and groups match ignoring case. Encode spaces as %20.
  • toggle on a group or all switches them all on if none is on, otherwise all off.
  • open brings up Settings, selecting the named tunnel if given.

Examples#

In a shell script#

Switch environments before running a migration, and back afterwards:

#!/bin/zsh
set -e
portkeep start "Staging MySQL" --wait  # switches off anything else on 3306
./migrate --host 127.0.0.1 --port 3306
portkeep stop "Staging MySQL"

Without waiting for the result, from anywhere:

open -g "portkeep://start?group=Development"

Raycast#

Create a Quicklink (Raycast › Create Quicklink) with a link such as portkeep://toggle?group=Production. Or write a Script Command that calls portkeep:

#!/bin/zsh
# @raycast.schemaVersion 1
# @raycast.title Start Orders MySQL
# @raycast.mode silent
portkeep start "Orders MySQL"

Raycast Script Commands may not load your shell profile; if portkeep isn’t found, use its full path (/opt/homebrew/bin/portkeep for Homebrew on Apple silicon, or wherever which portkeep points).

Shortcuts#

Add an Open URLs action with portkeep://start?name=Orders%20MySQL, or a Run Shell Script action that runs portkeep status "Orders MySQL" and uses its output. Portkeep has no Shortcuts actions of its own yet.

Every tunnel that isn’t connected, with what to do about it:

portkeep list --json | jq -r '.tunnels[] | select(.state != "connected" and .state != "off") | "\(.name): \(.hint // .status)"'

AI assistants#

Claude, Cursor and other assistants can use the same operations through portkeep mcp, or by running portkeep … --json themselves. See AI assistants.
