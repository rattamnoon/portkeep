The menu

Click the Portkeep icon in the menu bar to open the menu. It lists every tunnel under its group with its local port and live status, and has a switch for each tunnel, each group, and everything at once.

Header and master switch#

The top of the menu shows how many tunnels are connected out of how many you have, for example 3 of 6 connected. The switch on the right starts or stops every tunnel:

  • It is on while any tunnel is on.
  • Switching it on starts all tunnels. Tunnels that share a local port aren’t started together: the first one in the list wins and the others stay off.
  • Switching it off stops all of them.

If Portkeep couldn’t read or save tunnels.json, a one-line notice appears under the header. See Files.

Group tabs#

When tunnels sit in more than one group, a row of tabs appears under the header: All, then one per group that has tunnels, each with its colour dot and a connected count such as Production 1/3. Pick a tab to show only that group. The menu remembers the last tab you chose; if that group no longer has tunnels it goes back to All.

Groups and group switches#

Tunnels are listed under their group, in the order of Settings › Groups & Tags. Groups with no tunnels aren’t shown. Each group header has its own small switch:

  • It is on while any tunnel in the group is on.
  • Switching it on starts every tunnel in the group, one per local port, the first in the list winning.
  • Switching it off stops every tunnel in the group.

Tunnel rows#

Each row shows, from left to right:

  • A method icon. It is filled with the accent colour while the tunnel is active (connecting, connected, reconnecting or standing by) and grey when it is off or stopped on a problem. The icons are a terminal for SSH, a cloud for AWS SSM, a box for Kubernetes, a shield for Google Cloud IAP, a globe for Cloudflare Access, and </> for a custom command.
  • The name and local port, such as Postgres :5432.
  • The status line, such as Connected · 2h 14m. It wraps to two lines when the tunnel needs attention. Every status is listed in Status and troubleshooting.
  • A warning triangle when the tunnel has stopped on something only you can fix: a taken port, an expired sign-in, a changed host key and so on. A tunnel that is reconnecting on its own has no triangle.
  • The ⋯ button, shown when you hover over the row and always shown while the tunnel needs attention.
  • The switch. On means Portkeep keeps this tunnel up; off stops it.

Switching on a tunnel whose local port another tunnel is using switches that other tunnel off first. That is how one port can serve several environments.

A long list scrolls inside the menu, so the menu stays on screen. With no tunnels yet it reads No tunnels yet and Add one, or pick a host from ~/.ssh/config.

The ⋯ menu#

The ⋯ button on a row opens these actions. The first one depends on what is wrong, and only appears when there is something to fix:

ItemWhenWhat it does
Use Port NThe local port is taken by another program, and Portkeep knows which.Moves the tunnel to a free port (the first free one from your port + 10000 up, otherwise from 20000 up), saves it and switches it on.
Sign In to AWS…An AWS SSM tunnel stopped because the profile’s sign-in expired, and its Offer AWS sign-in setting is on.Runs aws sso login --profile <profile>, which opens your browser to sign in, then tries the tunnel again.
Retry NowThe tunnel is waiting to reconnect, stopped on a failure, or blocked by a taken port (after the fix above, if there is one).Skips the wait and tries again straight away, with the backoff reset.
Change Local Port…Always.Asks for a new port (1 to 65535) and saves it. A running tunnel restarts on the new port.
Copy AddressAlways.Copies 127.0.0.1:<port> for pasting into a client.
Edit Tunnel…Always.Opens the tunnel in the Settings window.
DuplicateAlways.Adds a copy with every setting, named “<name> copy” (then “copy 2” and so on), switched off and placed right after the original, and opens it in Settings. The quick way to add Development next to Production.
Show LogAlways.Opens a window with the last 500 lines the tunnel’s tool printed. See Logs.
Copy DiagnosticsAlways.Copies the versions, the tunnel’s settings, state and last 50 log lines as Markdown for a bug report. See Diagnostics.

Add Tunnel, Settings and Quit#

  • Add Tunnel… opens the Add Tunnel window.
  • Settings opens the Settings window on the first tunnel.
  • Quit stops every tunnel’s process before Portkeep exits, so no ssh or aws process is left running. Tunnels that were on come back at the next launch unless you turn that off in General.

The menu bar icon#

The icon is a monochrome bracket-and-dot mark, [•], drawn as a template image so it matches the menu bar in light and dark mode. When any tunnel needs attention a small dot appears at its top right. That happens while a tunnel is:

  • reconnecting after a drop,
  • blocked because its local port is taken, or
  • stopped on a failure such as an expired sign-in or a changed host key.

VoiceOver reads the icon as “Portkeep: N connected”, adding “needs attention” when the dot shows.
