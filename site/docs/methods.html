Connection methods

Portkeep opens each tunnel by running a command-line tool with your existing configuration and sign-ins. This page lists, for each method, the command it runs, what you need installed, every field, and a worked example.

On this page

  2. SSH
  3. AWS SSM
  4. Kubernetes
  5. Google Cloud IAP

  7. Custom Command

How every method runs#

  • Portkeep finds each tool on your login shell’s PATH, or uses the path you set in Settings › Tools. The tool runs with that PATH, so aws can find session-manager-plugin.
  • The tool gets no keyboard input. Anything that would stop to ask for a password, passphrase or one-time code fails instead, so sign-in must already work without typing.
  • Everything the tool prints goes to the tunnel’s log, and Portkeep reads the last lines to explain a failure.
  • The tunnel counts as Connected once 127.0.0.1 on the local port accepts a connection, within 20 seconds of starting.
  • The Runs box in the editor shows the exact command before you save.

SSH#

Runs ssh from your login shell’s PATH (normally /usr/bin/ssh; the Tools page shows which, and can point it elsewhere) with your ~/.ssh/config, keys and agent. Use it for a database or service behind a bastion, for a SOCKS proxy, or to expose a local port on a server.

Forwarding
Local (-L, the default), Remote (-R) or SOCKS (-D).
Host
The SSH host to connect to: an alias from ~/.ssh/config or user@host. Required.
Jump through
Optional jump host, passed as -J (ProxyJump). Empty means none. A ProxyJump line in your SSH config works too.
Destination
Host and port at the far end, for Local and Remote. Not shown for SOCKS. Required.

Every SSH tunnel runs with -N (no remote command), -o ServerAliveInterval=<keep-alive> and -o BatchMode=yes, which makes ssh fail rather than prompt.

Local forwarding (-L)#

Your Mac’s local port reaches Destination as the SSH host sees it. Use localhost for a service on the SSH host itself.

ssh -N -L 5432:db.internal:5432 -J jump -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o BatchMode=yes bastion

Remote forwarding (-R)#

The other way round: the SSH host opens Local port on its side, and connections to it reach Destination as your Mac sees it, for example localhost:3000 for a dev server on your Mac.

ssh -N -R 8080:localhost:3000 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o BatchMode=yes devbox

Nothing listens on your Mac, so Portkeep doesn’t check the local port and can’t probe the forward: it counts the tunnel as connected once ssh has been running for 3 seconds, and reconnects when ssh exits. On-demand start isn’t available for remote forwarding.

SOCKS proxy (-D)#

A SOCKS proxy on your Mac’s local port that sends traffic out through the SSH host. Point a browser or tool at 127.0.0.1 on that port as a SOCKS5 proxy.

ssh -N -D 1080 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o BatchMode=yes jump

SSH Advanced Options#

Identity file
A private key to use, passed as -i (~ is expanded). Empty means ssh-agent and your SSH config decide. The key must not need a passphrase typed; add passphrase keys to the agent with ssh-add --apple-use-keychain.
Keep-alive (seconds)
Default 30. Passed as ServerAliveInterval, so ssh notices a dead connection and exits.
Fail if the port can’t be forwarded
On by default. Adds -o ExitOnForwardFailure=yes, so ssh exits instead of staying connected without the forward.
Compression
Off by default. Adds -C.
Extra arguments
More ssh options, such as -o LogLevel=ERROR. Split into words like a shell would, with quotes respected, but variables and wildcards aren’t expanded.

Example: Postgres behind a bastion#

A database at db.staging.internal:5432 that only the bastion can reach, with bastion defined in ~/.ssh/config:

  1. Name Postgres, Group Staging, Tag db.
  2. Forwarding Local, Host bastion, Destination db.staging.internal : 5432.
  3. Local port 5432. Your client connects to 127.0.0.1:5432.

AWS SSM#

Runs aws ssm start-session with AWS Session Manager port forwarding. It needs the AWS CLI and session-manager-plugin:

brew install awscli
brew install --cask session-manager-plugin
Profile
The AWS profile to use, as in ~/.aws/config. Default default.
Region
Required. Filled in from the profile when you pick one and Region is empty.
Instance ID
The instance Session Manager connects to, such as i-0123456789abcdef0. Passed as --target.
Forward to
Remote host (the default): a host the instance can reach, such as an RDS endpoint. The instance: a port on the instance itself.
Remote host
Shown for Remote host. The host name or address as the instance sees it.
Remote port
The port on the remote host, or on the instance.

To a remote host, Portkeep runs the AWS-StartPortForwardingSessionToRemoteHost document:

aws ssm start-session --profile prod --region ap-southeast-1 --target i-0a3f5c9e2b7d41f08 --document-name AWS-StartPortForwardingSessionToRemoteHost --parameters host=orders.cluster-ro.internal,portNumber=3306,localPortNumber=3306

To the instance, it runs AWS-StartPortForwardingSession:

aws ssm start-session --profile prod --region ap-southeast-1 --target i-0a3f5c9e2b7d41f08 --document-name AWS-StartPortForwardingSession --parameters portNumber=8080,localPortNumber=8080

AWS sign-in (SSO)#

When an SSO profile’s session has expired, the tunnel stops with AWS sign-in expired for profile prod. rather than retrying. Choose Sign In to AWS… in the row’s ⋯ menu: Portkeep runs aws sso login --profile prod, which opens your browser, and tries the tunnel again when it finishes.

Advanced Options has one SSM setting, Offer AWS sign-in when the session expires, on by default. Switch it off and an expired sign-in offers only Retry Now, for when you sign in your own way.

Example: RDS through an SSM instance#

An RDS MySQL database that only instances in its VPC can reach, and an instance i-0a3f5c9e2b7d41f08 with the SSM agent in that VPC:

  1. Install the AWS CLI and session-manager-plugin, and check that aws sso login --profile prod (or your usual sign-in) works in Terminal.
  2. Open Add Tunnel… and choose AWS SSM.
  3. Name Orders MySQL, Group Production. Profile prod; check that Region filled in, or type it. Instance ID i-0a3f5c9e2b7d41f08.
  4. Forward to Remote host, Remote host orders.cluster-ro.internal (the RDS endpoint), Remote port 3306, Local port 3306.
  5. Press Test Connection, then Add Tunnel, and switch it on in the menu. Connect your MySQL client to 127.0.0.1:3306.

To keep a Development copy on the same port, use Duplicate and change the group, instance and endpoint. Switching one on switches the other off. See Shared ports.

Kubernetes#

Runs kubectl port-forward with your kubeconfig contexts. It needs kubectl (brew install kubectl).

Context
The kubeconfig context, picked from kubectl config get-contexts or typed. Required.
Namespace
Default default.
Resource
What to forward to, in kubectl’s type/name form: svc/grafana, deploy/api or pod/api-7d9f.
Remote port
The port on the service or pod.

The forward listens on 127.0.0.1 only:

kubectl --context prod -n analytics port-forward svc/clickhouse 8123:8123 --address 127.0.0.1

kubectl port-forward exits when its connection to the pod breaks, for example when the pod restarts. Portkeep runs it again with the same settings, so it picks up the new pod.

Example: ClickHouse through a service#

  1. Name ClickHouse, Group Production, Tag analytics.
  2. Context prod, Namespace analytics, Resource svc/clickhouse, Remote port 8123.
  3. Local port 8123. If a local clickhouse-server already listens there, the field says In use: pick another port such as 18123, or use Use Port 18123 from the ⋯ menu later.

Google Cloud IAP#

Runs gcloud compute start-iap-tunnel through Identity-Aware Proxy. It needs the gcloud CLI, signed in (brew install --cask google-cloud-sdk, then gcloud auth login).

Project
The Google Cloud project ID.
Zone
The instance’s zone, such as asia-southeast1-a.
Instance
The VM’s name.
Remote port
The port on the VM.
gcloud compute start-iap-tunnel db-1 5432 --local-host-port=localhost:5432 --zone asia-southeast1-a --project my-project

Cloudflare Access#

Runs cloudflared access tcp for a TCP application behind Cloudflare Access. It needs cloudflared (brew install cloudflared), which signs in through the browser.

Hostname
The Access application’s hostname, such as db.example.com.
cloudflared access tcp --hostname db.example.com --url localhost:5432

Custom Command#

Runs any command that holds a port open, for tools Portkeep has no form for. It is run with /bin/zsh -c, with {port} replaced by the tunnel’s local port and your login shell’s PATH.

Command
The command line, such as tsh proxy db --port {port} mydb. Use {port} where the local port goes.

For Portkeep to manage it, the command must:

  • stay running in the foreground for as long as the tunnel is up. When it exits, Portkeep counts that as a drop and runs it again;
  • listen on 127.0.0.1 on the local port within 20 seconds. Portkeep watches the port, not the output;
  • not ask for input.

Without {port} in the command, it must listen on the Local port you set, and on-demand start isn’t available, because Portkeep can’t move the command to another port while it holds yours.
