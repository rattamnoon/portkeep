Adding and editing tunnels

A tunnel is a name, a local port and a way to connect. You add one in the Add Tunnel window and change it later in Settings; both use the same form, described field by field here.

The Add Tunnel window#

Open it with Add Tunnel… in the menu, the + button under the Settings sidebar, or Add Tunnel… on the empty Settings page. The left side lists the methods under Connect with, each with the tool it runs:

MethodRuns
SSHssh -L / -R / -D
AWS SSMaws ssm start-session
Kuberneteskubectl port-forward
Google Cloud IAPgcloud start-iap-tunnel
Cloudflare Accesscloudflared access tcp
Custom CommandAny command that holds a port open

The right side is the form for the chosen method. You can switch methods while filling it in; what you typed for one method is kept if you come back to it. Grey text in an empty field, such as e.g. Dashboard MySQL, is an example, not a value.

Name, group and tag#

Name
What the tunnel is called in the menu, in notifications and on the command line. Required. Names don’t have to be unique, but the command line acts on every tunnel with the name you give it.
Group
The heading the tunnel sits under, such as Production or Development. Pick one from the list or type a new name. Empty means Other. Portkeep starts with Production, Staging, Development, Local and Other; manage them in Groups & Tags.
Tag
One optional label, such as db or readonly. Pick one or type a new one; a coloured chip below the field previews it. A tunnel has at most one tag. Tags are searchable in the Settings sidebar.

Method fields#

The next section is titled with the method’s name and holds its fields: host and destination for SSH, profile and instance for AWS SSM, and so on. Each method’s fields, defaults and the command they produce are on the Connection methods page.

Fields that take a host, profile or context have a small picker button beside them with the values you already have:

  • SSH Host and Jump through: the Host aliases in ~/.ssh/config, skipping wildcard patterns. Files pulled in with Include aren’t read for this list.
  • AWS SSM Profile: the [default] and [profile …] sections of ~/.aws/config. Picking a profile fills in Region from it when Region is empty.
  • Kubernetes Context: the output of kubectl config get-contexts -o name.

Local port#

The port on your Mac that your client connects to, from 1 to 65535; point the client at 127.0.0.1 on this port. As you type, a hint beside the field says:

  • Available: nothing is listening there.
  • In use: another program is listening there. You can still save, but the tunnel won’t start until the port is free.
  • Shared with <name>: another tunnel uses the same port. That is allowed, and switching one on switches the other off. See Shared ports.

For SSH remote forwarding this is the port opened on the server instead.

Connect at login#

When on, the tunnel starts every time Portkeep launches, whether or not it was on when Portkeep quit. While at least one tunnel has this on, Portkeep adds itself to your login items so it opens when you log in; when none do, it removes itself.

Advanced Options#

Click anywhere on the Advanced Options row to show or hide it. Every method has the on-demand options; SSH and AWS SSM have a few of their own, described on the methods page.

Start when an app connects
Off by default. When on, switching the tunnel on makes Portkeep hold the local port itself and show Standing by · starts when an app connects; the real tunnel starts when a client connects. Not available for SSH remote forwarding, or for a custom command without {port}. See On demand.
Stop after minutes idle
Shown when the option above is on. Default 10. After this many minutes with no connections the tunnel stops and goes back to standing by. 0 keeps it running once started.

The Runs preview#

The Runs box shows the exact command Portkeep will run, built from the fields as you type, with the tool’s file name and every argument. You can select and copy it to try in a terminal. Below it, a line says what the method needs, such as Needs the AWS CLI and session-manager-plugin.

  • Until every required field holds a valid value, the box reads Fill in the fields above to see the command.
  • If the tool can’t be found it says so, with the install command: kubectl not found. Install it with brew install kubectl. Install it, or set its path in Settings › Tools.

Portkeep never runs your tunnel through a shell, except for Custom Command: the arguments are passed to the tool as they appear.

Test Connection#

Test Connection runs the tunnel once, without saving it, until it connects or fails, then stops it. The result appears next to the button:

  • Connected. Port 3306 is open. when the local port accepted a connection;
  • otherwise the same message the menu would show, such as Host key changed for bastion. Check it, then remove the old key from known_hosts.

A tunnel set to start when an app connects is tested by connecting straight away. The test uses the local port you entered, so it reports the port as in use if another tunnel is running there.

Add Tunnel (or Return) saves the tunnel, switched off. It is enabled once the name, local port and the method’s required fields are filled in.

Editing a tunnel#

Pick a tunnel in the Settings sidebar, or use Edit Tunnel… in its ⋯ menu. The same form appears, with a Connect with picker to change the method. Then:

  • Save (⌘S) applies the changes. Revert puts the fields back as saved.
  • Changing the name, group or tag of a running tunnel doesn’t restart it.
  • Changing the local port, the connection fields or the on-demand options restarts a running tunnel with the new settings.
  • Moving a running tunnel onto a port another running tunnel holds switches that other tunnel off.

To remove a tunnel, select it in the sidebar and press −. Portkeep asks first, and the tunnel stops if it is running.
