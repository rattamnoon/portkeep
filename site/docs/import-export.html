Import and export

Move tunnels between Macs or share a set with a teammate as a JSON file, and turn the forwards you already have in ~/.ssh/config into tunnels. All three live in Settings › General › Tunnels.

On this page

  1. Export Tunnels
  2. Import Tunnels
  3. Import from SSH Config

Export Tunnels#

Export Tunnels… saves a JSON file (named Portkeep Tunnels.json by default) with:

  • every tunnel and its settings,
  • your groups and tags, and their colours.

It leaves out your tool paths, which belong to this Mac, and anything about what is running. It holds no secrets, because Portkeep keeps none, but it does contain host names, instance IDs, profiles and the like, so share it as you would your SSH config. The button is greyed out while you have no tunnels.

Import Tunnels#

Import Tunnels… reads a file from Export Tunnels, or a tunnels.json copied from another Mac. Then:

  • Each tunnel is added under a new id, switched off.
  • A tunnel that is already here with exactly the same settings (name included) is skipped, so importing the same file twice adds nothing the second time.
  • Groups and tags the file has that you don’t are added, with their colours. Your existing colours are kept.

It ends with a summary such as Imported 4, skipped 2, adding Skipped tunnels are already here with the same settings. when something was skipped. A file that isn’t either kind gives It isn’t a Portkeep export or tunnels.json.

Imported tunnels use this Mac’s tools and your local SSH config, AWS profiles and kubeconfig, so check that the hosts, profiles and contexts they name exist here.

Import from SSH Config#

If you already keep forwards in ~/.ssh/config, Import from SSH Config… lists them as SSH tunnels to add:

Host bastion
  HostName bastion.example.com
  LocalForward 5432 db.internal:5432
  LocalForward 6379 redis.internal:6379

Host jump
  DynamicForward 1080

That file offers three tunnels: bastion 5432 (127.0.0.1:5432 → db.internal:5432), bastion 6379, and jump 1080 (a SOCKS proxy on 127.0.0.1:1080).

What it reads#

  • LocalForward and DynamicForward lines under a named Host. Each named alias on a Host line gets its own tunnel; wildcard patterns (*, ?, !) and Match blocks are skipped.
  • Files pulled in with Include, including globs such as Include config.d/*, with ~ expanded and relative paths taken from ~/.ssh, up to 16 levels deep.
  • Listen addresses such as 127.0.0.1:5432 or [::1]:5432: only the port is used. Forwards to or from a Unix socket are skipped. RemoteForward lines aren’t offered.

Adding them#

Each forward appears with a checkbox, named “<host> <port>”. Forwards you already have as tunnels show Already added and can’t be picked again; the rest start ticked. Choose a Group for them (default Other) and press Add N Tunnels. They are added switched off, as SSH tunnels with the default advanced options, and you can rename them afterwards.

When nothing is found the sheet says No LocalForward or DynamicForward lines under a named Host.

ssh opens every forward of a host. Your LocalForward lines stay in ~/.ssh/config, and ssh opens all of a host’s forwards whenever it connects to that host. So when the bastion 5432 tunnel runs, ssh bastion also takes port 6379, and the bastion 6379 tunnel then finds its port in use. Tunnels from a host with several forwards therefore run one at a time. To run them side by side, remove those LocalForward lines from ~/.ssh/config after adding the tunnels: Portkeep passes each forward on the command line itself.
