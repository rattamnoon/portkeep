FAQ and limits

Basics#

How do I keep an SSH tunnel alive on macOS?#

Add it to Portkeep and switch it on. Portkeep restarts the tunnel after sleep, a network change or a dropped session, backing off from 1 s to 60 s between tries and spending none while you’re offline. It shows Connected only when the local port actually accepts connections, and tunnels that were on when it quit come back at the next launch. See Reconnecting.

Is Portkeep an autossh alternative?#

Yes, for keeping port forwards up. Like autossh it restarts ssh when the connection drops, and it adds a menu bar switch and live status per tunnel, a check that the local port is free before starting, and a plain-language reason when a tunnel fails. It also drives AWS SSM, kubectl, Google Cloud IAP, Cloudflare Access and custom commands, not only SSH.

Is Portkeep free?#

Yes. Portkeep is free and open source under the MIT License, and the code is on GitHub.

How do I install Portkeep?#

Run brew install --cask rattamnoon/tap/portkeep, or download the .dmg from GitHub Releases and drag Portkeep to Applications. It needs macOS 14 Sonoma or later, on Apple silicon or Intel. Releases aren’t notarized yet, so the first time, right-click Portkeep in Applications and choose Open. See Install.

I can’t find the menu bar icon.#

On a Mac with a notch, a full menu bar can hide it. Open Portkeep again from Finder or Spotlight and the Settings window comes up; you can start and stop tunnels there too.

Connecting#

How do I port forward to RDS through AWS SSM from my Mac?#

Add a tunnel with the AWS SSM method, pick your AWS profile, enter the ID of an instance that can reach the database, and set the RDS endpoint and port as the remote host and port. Portkeep runs aws ssm start-session for you and keeps it up. You need the AWS CLI and session-manager-plugin. There is a step-by-step example.

Why does kubectl port-forward keep disconnecting, and how does Portkeep handle it?#

kubectl port-forward exits when its connection to the pod breaks, for example when the pod restarts, the laptop sleeps or the network changes, and it does not restart on its own. Portkeep notices, says so in the menu, and runs it again with the same service, deployment or pod and kubeconfig context, backing off between tries.

Can Portkeep type my SSH password or passphrase?#

No. Portkeep runs ssh with BatchMode=yes and no keyboard input, so anything that prompts fails with bastion refused the key. or a similar message. Use a key in your agent; for a key with a passphrase, add it once with ssh-add --apple-use-keychain. The same goes for OTP and other interactive sign-ins.

My AWS SSO session expired. Do I have to open Terminal?#

No. The tunnel stops with AWS sign-in expired for profile prod.; choose Sign In to AWS… in its ⋯ menu, finish signing in in your browser, and Portkeep tries again.

My tool isn’t listed. Can Portkeep still run it?#

Yes, with Custom Command, as long as the command stays running and listens on the local port. Put {port} where the port goes and Portkeep fills it in.

Does Portkeep store my passwords or keys?#

No. Portkeep never stores passwords, keys or tokens. It runs the tools you already use with your existing ~/.ssh/config, AWS profiles and kubeconfig, and makes no network connections of its own. See Privacy.

Ports#

How do I switch between production and development databases on the same port?#

Give both tunnels the same local port, such as 3306. Switching one on switches the other off first, so changing environment is one click and your database client keeps the same address. See Shared ports.

It says the port is in use. By what?#

The row names the process, such as Port 8123 is in use by clickhouse-server. Choose Use Port 18123 in the ⋯ menu to move the tunnel to a free port, or stop the other program. See Port conflicts.

I imported forwards from my SSH config and only one runs at a time.#

ssh opens every LocalForward of a host whenever it connects to it, so the first tunnel takes all of that host’s ports. Remove those lines from ~/.ssh/config after importing. See Import from SSH Config.

Can a tunnel run only while I’m using it?#

Yes. Turn on Start when an app connects in Advanced Options. Portkeep holds the port, opens the real tunnel when your client connects, and stops it after 10 idle minutes (or your own number; 0 never stops). See On demand.

Limits in this version#

  • Sign-in must work without typing. Passwords, passphrase prompts and OTP aren’t supported yet. Add passphrase keys with ssh-add --apple-use-keychain.
  • No sync between Macs, and no team sharing beyond exporting a file.
  • No Shortcuts actions of its own yet; a shortcut can open a portkeep:// URL or run the portkeep command.
  • On-demand tunnels proxy TCP on 127.0.0.1 only, and an app that holds connections open keeps the tunnel up.
  • One tag per tunnel.
  • Releases aren’t notarized yet, so macOS asks before the first launch. Builds from source are ad-hoc signed, and macOS warns when you open a copy on another Mac.
  • Not on the Mac App Store, because the sandbox would stop it running your CLIs and reading your config.
  • Failure messages come from the tool’s English output. A tool that prints something Portkeep doesn’t recognise shows its exit status instead; the log has the full text.
