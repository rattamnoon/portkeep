Files, backup and privacy

Portkeep keeps a handful of plain files in one folder, stores no secrets, and makes no network connections of its own. This page lists the files, how to back them up, and how to remove Portkeep completely.

Where things live#

Everything is in ~/Library/Application Support/Portkeep/:

FileWhat it holds
tunnels.jsonYour tunnels, groups, tags, colours and tool paths. Plain JSON, safe to back up, and safe to edit while Portkeep is quit.
session.jsonWhich tunnels are switched on, so the next launch can turn the same ones back on. Written the moment you switch one, so it survives a crash or a forced restart.
running.jsonThe process IDs Portkeep started, so after a crash the next launch can stop any that are still running. It only stops a process whose start time matches, so it never touches an unrelated process that reused the ID.
status.jsonWhat each tunnel is doing right now, for the portkeep command and your scripts. Written by the app, never read back.

App preferences (language, notifications, reopening tunnels, the last group tab) are in the usual macOS preferences for com.rattamnoon.portkeep. Tunnel logs are kept in memory only.

tunnels.json#

The file Portkeep reads at launch and rewrites whenever you change something. A trimmed example:

{
  "groupColors" : { "Production" : "#FF3B30" },
  "groups" : [ "Production", "Staging", "Development", "Local", "Other" ],
  "schemaVersion" : 1,
  "tagColors" : { "db" : "#007AFF" },
  "tags" : [ "db" ],
  "toolPaths" : { "kubectl" : "/opt/homebrew/bin/kubectl" },
  "tunnels" : [
    {
      "connectAtLogin" : false,
      "group" : "Production",
      "id" : "9F1C2A4E-6B3D-4C1A-9E57-2D8B0F6A1C33",
      "idleMinutes" : 10,
      "localPort" : 3306,
      "method" : {
        "ssm" : {
          "forwardTo" : { "remoteHost" : { "host" : "orders.cluster-ro.internal", "port" : 3306 } },
          "profile" : "prod",
          "region" : "ap-southeast-1",
          "ssoAutoLogin" : true,
          "target" : "i-0a3f5c9e2b7d41f08"
        }
      },
      "name" : "Orders MySQL",
      "startsOnConnect" : false,
      "tags" : [ "db" ]
    }
  ]
}

method has exactly one key: ssh, ssm, kubernetes, iap, cloudflare or custom, holding that method’s fields.

  • If the file can’t be read (for example, a hand edit broke the JSON), Portkeep doesn’t overwrite it. It moves it aside to tunnels.json.broken-<date>, such as tunnels.json.broken-20261017-091500, starts empty, and says so at the top of the menu. Fix the file, quit Portkeep, and move it back.
  • If it was written by a newer Portkeep, it is opened read-only, with tunnels.json was written by a newer Portkeep. Changes won’t be saved.
  • Top-level keys Portkeep doesn’t know are kept when it saves.

Backup and moving to another Mac#

  • Back up tunnels.json; it is the only file you need. The others only record what is running.
  • To move tunnels, use Export and Import Tunnels, which adds to what is already there and leaves out tool paths that only make sense on this Mac. Copying tunnels.json into the folder instead replaces everything there; do it while Portkeep is quit.
  • There is no sync between Macs.

Uninstall#

Quit Portkeep first (Quit in its menu), which stops every tunnel. Then:

  • Homebrew: brew uninstall --cask portkeep removes the app and the portkeep command. Add --zap to also delete the data folder and preferences:
brew uninstall --zap --cask portkeep
  • Otherwise: move Portkeep from Applications to the Trash, then delete ~/Library/Application Support/Portkeep and ~/Library/Preferences/com.rattamnoon.portkeep.plist. If you used Install Command Line Tool…, remove the portkeep link from /usr/local/bin or ~/.local/bin.

If any tunnel had Connect at login, switch it off before uninstalling so Portkeep removes itself from your login items, or remove it in System Settings › General › Login Items.

Privacy#

  • No secrets. Portkeep stores no passwords, keys or tokens. Sign-in is left to the tools it runs and the agent, keychain, SSO cache or kubeconfig they already use.
  • No network connections of its own. Portkeep has no analytics, no crash reporting and no update check. The only network traffic is what the tools you configure (ssh, aws, kubectl and so on) send, plus local connections on 127.0.0.1 to check that ports are open and, for on-demand tunnels, to pass your connections through.
  • What it reads. To fill its pickers it reads ~/.ssh/config (and, for Import from SSH Config, the files it includes), ~/.aws/config, and the output of kubectl config get-contexts. It runs lsof to name the process holding a taken port.
  • It isn’t sandboxed, which is why it isn’t on the Mac App Store: the sandbox would stop it running your CLIs and reading your config.
