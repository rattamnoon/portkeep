Use Portkeep with AI assistants

New in 0.4. Tell Claude, Cursor or another assistant “add a tunnel to prod MySQL through SSM” and it fills in the tunnel, tests it and switches it on, while you watch it appear in the menu. Assistants reach Portkeep through its MCP server or the portkeep command.

Connecting an assistant#

The Model Context Protocol (MCP) server is the portkeep tool inside the app, run as portkeep mcp. It forwards everything to the running Portkeep, starting it in the background if needed. Settings › General › AI assistants has both forms below ready to copy, with the right path for your Mac.

Claude Code#

claude mcp add portkeep -- /Applications/Portkeep.app/Contents/Resources/bin/portkeep mcp

Claude Desktop, Cursor and others#

Choose Copy MCP Config and paste it into the assistant’s MCP settings: claude_desktop_config.json (Claude Desktop › Settings › Developer › Edit Config), ~/.cursor/mcp.json for Cursor, or wherever your assistant keeps its MCP servers. Merge it with any servers already there.

{
  "mcpServers" : {
    "portkeep" : {
      "args" : [ "mcp" ],
      "command" : "/Applications/Portkeep.app/Contents/Resources/bin/portkeep"
    }
  }
}

Restart the assistant afterwards. If Portkeep isn’t in /Applications, the copied config has its real path.

Without MCP#

An agent that can run shell commands can use portkeep directly: every read takes --json, and add and edit take JSON. See JSON and changing tunnels.

The Portkeep skill#

The repository has a skill (SKILL.md, in the Agent Skills format) that teaches an agent the workflow and the rules: look up what is configured, read the method’s fields, add, test, start, and when something fails read the hint rather than guess. Install it for Claude Code:

git clone https://github.com/rattamnoon/portkeep.git
cp -R portkeep/skills/portkeep ~/.claude/skills/

The MCP server also gives the assistant a short version of the same instructions when it connects, so the skill is optional with MCP and most useful for agents that use the command line.

What an assistant can do#

ToolDoes
discoverLists the Host aliases in ~/.ssh/config, AWS profiles and regions, kube contexts, which tools are installed, and the ports tunnels use, so the assistant uses your real names.
describe_methodsEach connection method’s fields, defaults and an example tunnel.
list_tunnels, get_tunnelTunnels with their settings and state, and for a problem a reason and a hint saying what to do.
add_tunnel, update_tunnel, duplicate_tunnelCreate and change tunnels, with the same checks as the editor.
test_tunnelConnects once and stops, like Test Connection, for a saved tunnel or settings not saved yet.
start_tunnel, stop_tunnelSwitch a tunnel, a group or everything, and wait for the result.
tunnel_logsThe end of a tunnel’s log.
list_groups, list_tags, add_group, add_tagGroups and tags, with colours.
remove_tunnelDeletes a tunnel. Marked as destructive, so assistants ask you first.

Asking for things#

  • “Add a tunnel to the orders RDS in prod through SSM, instance i-0a3f5c9e2b7d41f08, on local port 3307.”
  • “Forward Grafana from the prod cluster’s monitoring namespace to port 3000 and start it.”
  • “Make a Staging copy of Orders MySQL that goes through staging-bastion instead.”
  • “Why is Prod MySQL red?”
  • “Switch everything in Development off.”

The assistant reads the reason and hint Portkeep gives for a failure. For an expired AWS sign-in, a changed host key or a key missing from the agent, the fix is a command for you to run, such as aws sso login --profile prod, and the assistant should tell you rather than run it.

What stays with you#

  • No secrets to hand over. Portkeep stores no passwords, keys or tokens; tunnels use your SSH agent and the AWS, gcloud and kubectl sign-ins you already have. Don’t paste a password into a tunnel for an assistant: there is no field for one.
  • Only on this Mac. The MCP server talks to Portkeep over a local socket only your user account can open, and Portkeep sends nothing to any AI service. What the assistant sees (your tunnels’ settings, states and logs) goes to it because you connected it.
  • The app stays in charge. Every change goes through Portkeep’s own checks and shows in the menu straight away; tunnels.json is only ever written by the app.

If it doesn’t work#

  • The assistant doesn’t list Portkeep’s tools. Check the path in the config exists (ls /Applications/Portkeep.app/Contents/Resources/bin/portkeep) and restart the assistant. Running portkeep mcp in Terminal should print “MCP server ready on stdio” and wait; press ControlD to end it.
  • “Portkeep isn’t answering on control.sock.” A Portkeep from before 0.4 is running. Quit it and open the new one.
  • A change is refused. The message names the field and why, such as SSH local forwarding needs destination {host, port}. The assistant can usually fix it on its own.
